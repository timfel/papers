In this paper, we present the \toolname debugger for investigating
non-deterministic failures with low overhead in a systematic, top-down
method, with a particular focus on tool-building issues in the
following areas: first, how we modify the base system in a
self-sustaining environment to record network communication without
breaking the development tools. Second, how we created short feedback
loops that helped us iterate over our algorithm to detect anomalies in
the network communication. Finally, how we extended an existing tool
suite to provide a state of the art back in time debugger that allows
developers to inspect runtime data.

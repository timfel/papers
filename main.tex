\begin{abstract}
  \acrlong{cop} extends object-oriented languages with dynamic
  adaption of behavior. \acrlong{ocp} orthogonally extends
  object-oriented run-times by integrating constraints, including
  support for constraints over mutable state, object identity, and the
  results of message sends. Using these two language extensions in
  conjunctions offers interesting opportunities.

  In this paper, we report on new mechanisms involving layers and
  constraints that evolved from our experiences with combining
  Babelsberg/JS, an Object-Constraint Language, and ContextJS, an
  implementation of \acrlong{cop} in JavaScript. First, our experience
  shows that it is desirable to dynamically adapt declarative
  constraints, which offer an orthogonal mechanism to the definition
  of imperative behavior, likewise at runtime. In this work, we show
  an extension to ContextJS to scope activation or refinement of
  constraints dynamically using layers.  Second, ContextJS already
  provides different activation mechanisms for layers, including
  dynamically or structurally scoped, or globally through system
  generated events. Constraints provide an activation mechanism based
  on arbitrary boolean expressions changing their value, allowing for
  interesting applications of behavioral adaption based on certain
  conditions.
\end{abstract}

\section{Background}

Babelsberg \cite{FelgentreffJOT14} is a design for \gls{ocp}
languages, and this work is based on its JavaScript implementation,
Babelsberg/JS \cite{FelgentreffECOOP14}. \gls{ocp} languages are
motivated by the observation that some issues in software development
lend themselves to a declarative specification, while others are more
directly expressed using imperative constructs. The goal of
Babelsberg/JS is to provide both paradigms in a cleanly integrated
fashion within JavaScript in a way that supports messages,
encapsulation, inheritance, mutable objects, and object identity in
constraints.

Babelsberg/JS extends and integrates both semantically and
syntactically with JavaScript. Constraints are ordinary JavaScript
expressions that are introduced using the keywords \verb!always! and
\verb!once!, the constraint being that the expression evaluates to
true. An \verb!always!  constraint then holds for the rest of the
execution, whereas a \verb!once!  constraint is redacted after being
solved one time. A translation mechanism executes constraint
expressions while keeping track of the dependencies between
encountered variables and fields. Babelsberg abstracts from the
details of the underlying solvers and can translate constraints in
different ways to hand to different solvers.

The system keeps track of the currently active constraints and, if
they become invalidated through imperative modifications, triggers the
solver to find a solution that satisfies them. If no solution can be
found, the modification that invalidated the constraints is rejected
and an exception is generated. Constraints in Babelsberg/JS are thus
useful to encapsulate \emph{system maintained assumptions}, and ensure
that these assumptions cannot be quietly invalidated.

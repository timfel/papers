\section{Introduction}

Sketch- and pen-based input 

Sketching and note-taking while thinking about a problem is a common task in
software engineering. User interfaces, objects, interactions, and even code is
sketched on whiteboards and on paper to present and discuss.

While pen-based input on digital devices are commonly used for interaction tasks
such as 3D modeling, note taking, or domain specific applications such as
calculators or musical notation tools. For specialized domains, some work has
been done to allow users to sketch controls to prototype user interfaces quickly
(Wong, SILK, Monet, ...). There has also been a long history of using pen-based
input for programming tasks, with the Sketchpad system by Ivan Sutherland
arguably the first to use pen-based gestures to express operations.

The contribution we are working towards is to allow users to sketch and script
graphical objects. In this paper, we present prototypical development tools in
which we can develop simple graphical applications using only sketching,
handwriting, and touch. Based on our initial experience with these tools, we
discuss various design directions that we feel are important if programming
tasks should ever feel like sketching.

\section{Sketching vs Programming}
\label{sec:sketch-vs-progr}

Sketching is a creative activity. Creative work often begins with phases of
doodling and sketching to figure out what and how one wants to make
something. These doodles might be done on actual pen and paper, or (more
recently) using digitizers and touch-based devices. One key feature of these
doodles is their low fidelity. They are immediate, imperfect. They can be
refined, re-drawn. The other feature is that hand-drawn sketches are \emph{easy}
to make. All you need is pen and paper (or digitizer and tablet), so you can
sketch and doodle anywhere, from the couch, on the bus, in the bathroom.

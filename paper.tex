\begin{abstract}
  Constraints are a useful technique to ensure desired properties in a
  software system. Object constraint programming provides a design to
  integrate constraints with dynamic, object-oriented programming
  languages. In this paper we present an application of this design to
  the Squeak/Smalltalk programming environment. Our implementation
  allows developers to encode multi-way constraints over objects and
  collections of these using existing, object-oriented abstractions
  and have the runtime maintain these constraints automatically. We
  argue that our implementation facilitates reactive applications by
  using constraints as a means to modularize dependencies between
  different parts of the system, and by decoupling the constraint
  satisfaction from the available event sources in the system.
\end{abstract}

\section{Introduction}
Constraints describe relationships between objects that should
hold. This could be that all numbers in Suduko row be different, that
a circuit simulation obeys the laws of physics, or that the width,
height and color depth of a bitmap image correspond to the available
data. Such constraints can be checked and satisfied by finding
appropriate assignments for the objects that participate in the
constraints.

Babelsberg\cite{felgentreff2014jot} is a design to integrate
constraints into dynamic, object-oriented languages in a way that
allows programmers to dynamically create and satisfy constraints on
objects. The design is a strict extension of the object-oriented
semantics of the underlying host language. Babelsberg uses
object-oriented method definitions to define constraints rather than a
constraint \ac{dsl}\cite{Squander,Enaml,AppleCocoaAutoLayout}. As a
consequence, Babelsberg respects encapsulation and object-oriented
abstractions. The design also supports solver features such as
constraint priorities\cite{borning-lisp-symbolic-computation-1992} and
incremental resolving\cite{freeman1990incremental}. Recently, the
design has been extended to allow multiple constraint solvers to
cooperate to find a solution\cite{felgentreff2014babelsbergjs}.

In a standard imperative programming language, constraint solving and
satisfaction is implemented explicitly, and developers have to use
observers or related patterns to resatisfy constraints when the system
state changes. In contrast, Babelsberg maintains constraints
automatically.

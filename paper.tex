\section{Introduction and Background}

Programming language implementation frameworks have become more and more popular
as they allow language implementers to use another high-level language and
useful reusable components, such as garbage collectors or caching mechanisms,
to implement virtual execution environments for dynamic languages.
These frameworks, however, often enforce certain implementation styles and are
usually designed to support only one kind of interpretation model.
RPython~\cite{Ancona:2007:RST:1297081.1297091}, a language implementation
framework maintained as part of the PyPy project, for example, is mainly used to
implement bytecode interpreters as it provides a tracing \ac{jit} compiler which
is designed to operate on bytecode.
Oracle's Truffle framework~\cite{Wurthinger:2013:OVR:2509578.2509581}, on the
other hand, is designed for implementing \ac{ast} interpreters and its \ac{jit}
compiler applies \ac{ast} nod rewriting and partial evaluation to significantly
increase runtime performance of a language.

...

\Squeak~\cite{ingalls1997back} is a Smalltalk dialect derived from the
Smalltalk-80 language specification.
Its default virtual machine OpenSmalltalkVM~\cite{openSmalltalkVM} is
bytecode-based, written in Slang, a restricted subset of Smalltalk, and features
a mostly handwritten \ac{jit} compiler.

...

mention Graal

...

In this paper, we present and compare the implementations of an \ac{ast}
interpreter and a bytecode interpreter both for \Squeak and written in
the Truffle framework.
We discuss implementation pitfalls and compare their performance with a micro
benchmark.


\section{Implementations}

In this section, we present two different approaches for implementing
\Squeak interpreters in Truffle.

\paragraph{AST Interpreter}

Since Truffle and Graal operate on \ac{ast}, the natural way of implementing a
\Squeak interpreter in it is to write an \ac{ast} interpreter.
However, \Squeak is traditionally bytecode-based, so bytecode streams need to
be transformed into appropriate \ac{ast} nodes.

\begin{figure}
  \centering
  \includegraphics[width=.9\linewidth]{resources/squeak-ast}
  \caption{Architecture of an \ac{ast} interpreter for Smalltalk in Truffle.}
  \label{fig:squeak-ast}
\end{figure}

\autoref{fig:squeak-ast} gives an overview of how the architecture of this setup
looks like.
For each Smalltalk method, Smalltalk code is first parsed into a \Squeak
\ac{ast}.
This \ac{ast} is then compiled to bytecode by \Squeak's compiler.
The Truffle interpreter has no direct access to the original \ac{ast} and can
therefore only operate on bytecode.
In order to transform the bytecode into corresponding nodes again, we have
implemented a custom decompiler which is able to reconstruct the original
\ac{ast} with Truffle nodes.
Finally, Truffle and Graal can execute this \ac{ast} and perform their
performance optimizations.

\begin{lstlisting}[language=Java]
@ExplodeLoop(kind = LoopExplosionKind.MERGE_EXPLODE)
Object executeLoopFast(VirtualFrame frame) {
 CompilerAsserts.compilationConstant(bcNodes.length);
 int pc = 0;
 int backJumpCounter = 0;
 try {
  while (pc >= 0) {
   CompilerAsserts.partialEvaluationConstant(pc);
   AbstractBytecodeNode node = bcNodes[pc];
   if (node instanceof ConJumpNode) {
    ConJumpNode jumpNode = (ConJumpNode) node;
    boolean c = jumpNode.executeCondition(frame);
    if (CompilerDirectives.injectBranchProbability(
         jumpNode.getProbability(JUMP), c)) {
     int successor = jumpNode.getJumpSuccessor();
     if (CompilerDirectives.inInterpreter()) {
      jumpNode.increaseProbability(JUMP);
      if (successor <= pc) backJumpCounter++;
     }
     pc = successor;
     continue;
    } else {
     int successor = jumpNode.getNoJumpSuccessor();
     if (CompilerDirectives.inInterpreter()) {
      jumpNode.increaseProbability(NO_JUMP);
      if (successor <= pc) backJumpCounter++;
     }
     pc = successor;
     continue;
    }
   } else if (node instanceof UncondJumpNode) {
    UncondJumpNode jumpNode = (UncondJumpNode) node;
    int successor = jumpNode.getJumpSuccessor();
    if (CompilerDirectives.inInterpreter()) {
     if (successor <= pc) backJumpCounter++;
    }
    pc = successor;
    continue;
   } else { pc = node.executeInt(frame); }
  }
 } finally {
  LoopNode.reportLoopCount(this, backJumpCounter);
 }
}
\end{lstlisting}

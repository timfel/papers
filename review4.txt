PAPER: 3
TITLE: Squeak Makes a Good Python Debugger
AUTHORS: Fabio Niephaus, Tim Felgentreff, Tobias Pape and Robert Hirschfeld

Overall evaluation: 2

----------- Overall evaluation -----------
This paper is a nice case study of composing Squeak and Python interpreters for the purpose of providing the Squeak debugging experience to Python programs. The key enabling technology is RPython, which can generate a JIT'd compiler from an interpreter. This paper composes PyPy and RSqueak, RPython implementations of Python and Squeak respectively.

The paper gives the impression that this composition was surprisingly easy. I would like to have seen some metric like number of changed lines of code. I also did not fully understand how modular this composition was - e.g. the text mentions "patches the PyPy bytecode loop". Does this mean that the PyPy source in RPython did not need to be customized but is instead dynamically integrated? If so that would be an important benefit to mention!

Squeak's debugger was also adapted surprisingly easily, even including hot swapping code. This is an impressive result, but I am a little suspicious that it can be so perfect - surely there are some problematic edge cases due to misalignments of Squeak and Python semantics? It would be informative to discuss any such limitations.

Overall a useful addition to the literature on language composition.

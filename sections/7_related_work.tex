\section{Related Work} \label{sec:RELATED_WORK}

Our concept of grouping behavior of related objects relates to a wide range of language based and tool based approaches.
Conceptually most approaches try to reduce code duplication by introducing new, more abstract concepts.
Some solutions, like Dynamic Text, offer tool support to not reduce, but better manage duplications. 

\subsection{Traits}
A trait~\cite{sharli2002traits}, an alternative approach to multiple inheritance~\cite{cardelli1984semantics}, is a programming language concept to structure independent concerns of an object.
It is a collection of methods without having any state and can, therefore, be inherited by many objects, while an object can inherit many different traits.
Both, object groups and traits, modularize behavior and can be used by many objects, but object groups are superior in their concreteness and immediacy.
Traits, as well as multiple inheritance, are introduced as an abstract language level feature and, if used in a given program, are required to execute the program.
In comparison, object groups are more concrete as they leave all the required information for execution and understanding in the object itself.
Furthermore, traits require beforehand planning or refactoring when implementing changes to a program.
Object groups offer immediate feedback as they manipulate living objects, changing their behavior instantly.

\subsection{Prototype-based Inheritance}
Prototype-based programming~\cite{taivalsaari2001prototype}\cite{taivalsaari2009simplifying} is an alternate approach for classes, where objects can
inherit attributes and functions from other objects.
Languages based on prototypes, like JavaScript or Self, allow dynamic replacement of an objects prototype, which offers a similar immediacy as object groups.
Compared to object groups, prototypes are less concrete as they introduce abstraction to objects when inherited by objects.

\subsection{Dynamic Text}
Dynamic Text \cite{Chiba2012WRN} is a tool-based approach that reduces the effects of duplication in scattered code that implements cross-cutting. 
It is an alternative to Aspect-oriented Programming \cite{Kiczales1997AOP}, but deliberately does not resolve tangling as concern implementations
are sometimes more understandable in conjunction.
This approach relates to our Object Groups in that both are solutions that do not resolve duplications, but rather provide tool support for managing duplications.

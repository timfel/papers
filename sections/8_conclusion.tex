\section{Conclusion} \label{sec:CONCLUSION}

We propose to extend Lively's object-centric development tools to work
on object groups. Developers may group available objects that share
behavior either visually, by clicking their graphical representation
or choosing them from a representation of the Morphic scene graph, or
programatically, by evaluating program statements that return
collections. The object-centric development tools then present the
shared behavior and allow to add and alter further behavior to all
group members.  Further, developers may use groups to evaluate
statements on all members of groups to propagate changes to all of
them and simultaneously.

With our approach, tools automatically handle duplicated code, while
the developer continues to interact with live objects. That is,
developers no longer choose between manual duplication of code to
multiple objects, unnecessary indirection in form of delegation, or
extended feedback cycles of traditional functional decomposition.

In the future, we want more of the Lively tools to work on groups of
objects. The Object Editor should visually distinguish between
object-specific and shared functions. Moreover, as our current
implementations only considers available members while modifying
groups, we want to explore first-class groups and automatic group
discovery.

Despite this, our extensions to the Object Editor already permit
developers to work on groups of objects and, thereby, effectively
scale the object-centric development approach from one to many
objects.
